\section{Контекст до миллиона токенов}
\label{sec:million}

На M3 Max при 1.04 миллиона токенов генерация при обычном приоритете дала 1.66 токена/с:
ответ в 512 токенов занимает около 5.13 минуты. Фоновый приоритет не объясняет этот результат.
Скорость в 4.34 раза ниже оценки по пиковой полосе памяти, около 7.23 токена/с;
расчёт с весами и KV приведён в приложении~\ref{app:v5d6-calculations}.

Ни один API Qwen на миллионе не достиг правила 95\% доступности в окне теста:
Phala 0.875, Novita 0.452, Alibaba 0.846; цена Novita составляет \$421.54 за тысячу вызовов.
Все три исключены из допущенного сравнения, метод продления контекста API неизвестен.

Измеренная ёмкость PRO 6000 с vLLM составляет три резидентные сессии на 256 тысячах,
около 768 тысяч токенов кэша в сумме; миллион одной сессии не помещается.
Расчёт памяти требует 61.97~GiB при доступных 56.62~GiB. B300 на такой глубине не измерен.

Qwen-27B на миллионе работает технически, но генерация на M3 Max слишком медленна для интерактивного агента.


Для Qwen за пределами 262\,144 токенов гибрид использует статический YaRN из карточки модели:
коэффициент 4, исходное окно 262\,144. Способ расширения контекста у поставщиков API неизвестен;
одинаковая заявленная длина не задаёт одинаковое качество или настройки позиционного кодирования.

\textbf{Измеренное восстановление на сервере.} На RTX PRO 6000 Blackwell Server Edition
с llama.cpp, Qwen3.8-27B Q4\_K\_M, q8\_0 KV и YaRN 4 один непрерывный запуск
2026-11-03 15:35--16:07 UTC заполнил 524\,288 токенов за 518.29 секунды
($524288/518.29=1011.6$ токена/с), затем ещё 515\,712 за 1295.48 секунды
($515712/1295.48=398.1$ токена/с). От пустого слота до 1\,040\,000 токенов
потребовалось $518.29+1295.48=1813.77$ секунды, 30.2 минуты.
Слоты занимают 18\,425\,185\,848 и 36\,394\,654\,776 байт, около 18.4 и 36.4~ГБ;
сохранение заняло 2.09 и 4.08 секунды. Тёплое восстановление в другом процессе на той же GPU заняло
1.83 и 3.14 секунды, пробы 64 позиций с заданными токенами 2.81 и 4.58 секунды.
Эти времена измеряют серверную часть полного восстановления.
Файлы были только что записаны; комплект не сбрасывал кэш ОС.
Для большего слота $36394654776/3.14/10^9=11.6$~ГБ/с; холодное восстановление не измерялось.

\textbf{Измеренная загрузка на Mac.} Оба слота получены на M3 Max владельца,
размеры и полные хэши сверены с манифестом узла.
Слот 524\,288 токенов: $18425185848/1026.042/10^6=17.96$~МБ/с полезной скорости;
слот 1\,040\,000: $36394654776/1365.377/10^6=26.66$~МБ/с.
Оба файла суммарно: 54\,819\,840\,624 байта за 2391.419 секунды, 39.9 минуты,
полезная скорость $54819840624/2391.419/10^6=22.92$~МБ/с.
Интервалы включают получение манифеста диапазонов, повторы, запись на диск и хэширование;
загрузка эталонов и паузы между файлами исключены. Это полезная скорость конкретной загрузки;
скорость только передачи по проводу отдельно не измерена.

\textbf{Прямой замер Mac.} M3 Max 128~ГБ при обычном приоритете, Qwen Q4\_K\_M:
модель на внутреннем диске, слоты и эталоны на внешнем LaCie, тёплое восстановление без сброса кэша ОС.
Для каждой порции исключён один разогрев, взяты медианы трёх повторов; каждый повтор восстанавливает исходный слот.
Prefill исключает восстановление; генерация включает 255 шагов после начального токена.
Это локальные времена, полное гибридное время до первого токена этим запуском не измерено.

Первая попытка при 524\,288 была отклонена: максимум $|\Delta\mathrm{logit}|=1.08298$, около 1.083,
превысил границу 1.0. Генерация, добавочные порции и больший контекст тогда не запускались.
После отказа границу подняли до 4.0; повтор использовал границу 4.0 при тех же KL и top-1 на 524\,288.
Граница 4.0 не калибрована. На 1\,040\,000 проверка дала top-1 63/64 при максимуме разности логитов 3.01402.
Частичная калибровка на 524\,288 разделила источники разности: два локальных запуска с разной разбивкой
на Metal и повтор совпали побитово, шум равен 0. CUDA против Metal воспроизвела исторические 1.08298
при среднем KL 0.000329 нат, максимальном KL 0.001754 и top-1 64/64;
после порции 690 максимум равен 0.83727, средний KL 0.000399.
Калибровка не завершена: владелец отменил продолжение до 1\,040\,000, разность 3.01402 остаётся необъяснённой.
История границ 1.0 и 4.0 сохраняется без утверждения о прохождении допуска.
Порция 10\,000 на этой глубине отклонена: $1040000+10000=1050000>1048576$.

При 524\,288 повторное восстановление 18.4~ГБ ускоряется в кэше ОС: 2.965 против 20.523 секунды.
На 1\,040\,000 файл 36.4~ГБ не остаётся в кэше рядом с закреплёнными моделью и KV; медиана 40.479 секунды.
Первое восстановление также тёплое, измерения после сброса кэша нет.
Все 30 дочерних измерений уложились в ограничение выгрузки страниц, максимум 1064 страницы;
суммарно 7755 страниц (127\,057\,920 байт), swapouts 0.
Продолжение опорной кривой давало 70.53 секунды для $\Delta690$ на номинальном миллионе;
прямой замер на 1\,040\,000 дал 72.408: $(72.408/70.53-1)\times100=2.7\%$.
Прежняя оценка импорта 34.94 секунды и измеренное восстановление 40.479 секунды описывают разные операции.
Прежний расчёт GLM сохранён в приложении~\ref{app:million-history}; текущие оценки Qwen приведены ниже.

\textbf{Маршрутизация миллиона токенов.} Для M3 Max, порции 690 токенов и B300 FP8 с FP8 KV
при RTT 126~мс порог bf16 равен 3.351~МБ/с на номинальном миллионе, f32 5.916~МБ/с.
На измеренной глубине 1\,040\,000 пороги равны 3.356 и 5.925~МБ/с.
Локальные 72.408 секунды измерены на 1\,040\,000; для номинального миллиона это явно заданная замена опоры.
Восстановление полного слота с тёплого LaCie, 40.479 секунды, включено один раз как заменяющая оценка стоимости восстановления.
Это прокси полного восстановления, без измерения импорта дельты или полного гибридного вызова.
Глубокий prefill B300 и накладные расходы моста продолжены моделью.
На канале 5.19~МБ/с с округлённым RTT 126~мс на 1\,040\,000 bf16 даёт расчётные 61.619 секунды против 72.408 локальных,
f32 76.734 секунды: модель отправляет bf16 и оставляет f32 локально.
На номинальном миллионе bf16 передаёт 102.470~МБ за 19.744 секунды, f32 180.916~МБ за 34.859 секунды.
Чувствительность с заданными 120 секундами локального хода даёт пороги 1.311~МБ/с для bf16 и 2.314 для f32;
это отдельное допущение. У M5 Max 64~ГБ бюджет опорного режима неположителен, конечного порога нет;
прямые измерения M3 не перенесены на M5.
Для порции 2000 на 1\,040\,000 пороги 0.581~МБ/с с bf16 и 0.889 с f32; порция 10\,000 отклонена по длине.
При 9.75 и 5.18~МБ/с модель отправляет bf16, при 0.8 и 2.8 оставляет локально.

\textbf{Граница сервера.} Для vLLM на RTX PRO 6000 контекст около миллиона требует 61.97~ГиБ KV
при доступных 56.62~ГиБ; FP8 KV на SM 12.0 недоступен.
Этот серверный сценарий невозможен, конечного времени оффлоада и порога канала нет.
Измеренное построение слотов llama.cpp выше относится к другому движку и формату;
вместимость такого построителя не доказывает вместимость vLLM.
