Agentic work on unified-memory machines is bound by context reading: an M3 Max needs 225 s to read a 10k-token chunk at 150k depth. We propose a division of labour: a shared server prefills new tokens, while the user's machine keeps the session and decodes. Batched decode shares only weight reads across sessions; each session still reads its own KV and recurrent state, so batching gains shrink with depth. The hybrid wins while client memory bandwidth suffices, and more so for models with less KV per token. A protocol keeps two growing copies of a session over the internet: token IDs go up, KV of new positions and recurrent state come down; a token log and resynchronization restore consistency. For Qwen3.8-27B, f32 state import has zero KL difference from local on 20 documents; bf16 rounds and halves recurrent state with no measurable KL effect; RULER f32 scores are equivalent within ±2 pp at 8k/32k/64k (margin chosen after 8k/32k results); at 128k equivalence is not established: 95.90% versus 95.81%. A 40-turn CUDA-Metal session survived a disconnect and resync but showed no speedup: only 2 turns ran remotely, with diagnostic snapshots and hashing on the critical path; a first fresh-context call cut TTFT by 26%. For a fully internal 100% Qwen scenario with owned M5 Max clients and a dedicated office PRO 6000, the hybrid costs less than an internal cluster from 4 people at light load and 2 at medium; heavy load exceeds client capacity; the hybrid never costs less than the cheapest admitted API at any priceable measured Qwen point. Price cohorts are partial; transferring cache fractions to the workload is an assumption.
