# Кому выгоден гибрид: текст по движку 22 (3 ноября, ~21:30Z)

Основа: текст аналитика от 3 ноября, исправленный по движку 22 (`9053089e`, Muse r5x4 ACCEPT) и по FACTS. Пойдёт в статью в начало и в конец, в стиле статьи. Расчёт сделан для команды, у которой Маки (M5 Max 64 ГБ) уже есть, а сервер для чтения контекста свой: купленный RTX PRO 6000 в офисе, канал 125 МБ/с. Нагрузка на человека: лёгкая 200 вызовов в день, средняя 800, тяжёлая 2 500. Тяжёлая нагрузка взята по интенсивности владельца; типичны лёгкая и средняя.

## Текст

Коротко: в гибриде тяжёлое чтение контекста делает сервер, а ответ пишет Мак.

**Кому выгодно**

- **Командам, которым нельзя отдавать код и данные наружу, при средней и тяжёлой нагрузке.**
  - Свой кластер на том же сервере гибрид обходит при средней нагрузке с 5 человек, при тяжёлой с 2.
  - Ответы пишут Маки, поэтому серверов нужно меньше: при средней нагрузке и 5 людях $130.33 против $245.62 на человека в месяц.
- **Тем, кто уже запускает модель на Маке и устал ждать.**
  - Порцию в 10 тыс. токенов на глубине 150 тыс. M3 Max читает 225 с.
  - Сервер считает её за секунды. Вместе с передачей около 426 МБ это примерно 3.4 с по офисному каналу 125 МБ/с или 85 с при 5 МБ/с.
  - Это выигрыш во времени. Больше всего он у владельцев M3 Max.
  - M5 Max сам читает заметно быстрее, и ему для выгоды нужен быстрый канал: на глубине 100 тыс. порог 34.5 МБ/с против 5.3 у M3 Max.
- **Тем, у кого сервер для чтения контекста общий и загружен.** Например, один сервер на несколько команд или сервис вроде Swarm Inference, который ведут авторы.
  - Тогда при тяжёлой нагрузке гибрид в 1.7 раза дешевле медианного API.
  - При средней нагрузке медианный API дешевле на 7%.
  - Это предел при полной загрузке сервера.
- **Командам с тяжёлой нагрузкой от 45 человек.** Со своим офисным сервером гибрид дешевле медианного API.
- **Тем, кому важна автономность.** Без сервера Мак продолжает работать, только медленнее, а сервер хранит копию сессии на случай сбоя.

**Кому невыгодно**

- **Командам с лёгкой нагрузкой и выделенным сервером.**
  - Сервер занят 3.6% рабочего времени, и при 50 людях медианный API в 11 раз дешевле гибрида.
  - Свой кластер на том же сервере тоже чуть дешевле, $61.41 против $68.93 на человека: обоим хватает одного сервера, а у гибрида есть расходы на человека.
- **Тем, кому нужна просто самая низкая цена, если облако допустимо.**
  - Самый дешёвый API той же модели при доле кэша 98.1% дешевле гибрида в 4.4 раза при тяжёлой нагрузке и в 55 раз при лёгкой.
  - Без кэша самый дешёвый API гибрид обходит только при тяжёлой нагрузке, с 74 человек.
  - Какая доля кэша у поставщиков на самом деле, ещё измеряется.
- **Тем, кто хочет купить Мак ради экономии.**
  - Новый M5 Max добавляет $69.05 на человека в месяц.
  - С ним гибрид не дешевле медианного API ни при какой нагрузке.
  - Свой кластер он обходит при средней нагрузке только с 34 человек.
- **Владельцам ПК с RTX 5090, для модели 27B с контекстом до 262 тыс. токенов.**
  - Карта сама читает контекст в 23 раза быстрее M3 Max и пишет ответ в 4.3–4.7 раза быстрее.
  - В её 32 ГБ помещается одна сессия на полной глубине.
  - Гибрид нужен там, где модель и контекст не помещаются в видеопамять: миллион токенов, несколько сессий сразу. Для крупных MoE-моделей это ожидание, без замера.
- **С медленным домашним интернетом.**
  - При 5.19 МБ/с предварительный расчёт оставил все ходы локальными.
  - На миллионе токенов с передачей в bf16 порог для M3 Max около 3 МБ/с.

**Важно про приватность**

Если сервер для чтения контекста чужой, он видит весь ваш контекст. Данные остаются внутри компании, только если сервер свой.

**Одной фразой**

Гибрид выгоден там, где Маки уже есть, сервер свой и загружен средней или тяжёлой работой, а данные нельзя отдавать наружу. При лёгкой нагрузке выделенный сервер простаивает, и API дешевле.

## Откуда числа

- **Движок 22** (FACTS, блок «Engine run 22»):
  - пересечения через 500 человек;
  - команда 50: 0.088 / 0.351 / 1.097 на выделенной базе, 0.313 / 0.934 / 1.701 на общей;
  - малые команды: 130.33 / 245.62, 68.93 / 61.41;
  - самый дешёвый API 0.018 / 0.072 / 0.225 при 98.1%, без кэша пересечение с 74 человек;
  - покупка Мака +69.05;
  - пороги на 100k: 5.305 и 34.475;
  - 1M bf16: 2.992 МБ/с.
- **225 с:** 10 000 / 44.4 ток/с, M3 Max при обычном приоритете, 150k, Δ10000.
- **426 МБ:** 10 000 × 34 816 Б кэша плюс 78.4 МБ состояния в bf16; 426 / 125 = 3.4 с, 426 / 5 = 85 с.
- **RTX 5090:** FACTS, блок клиента RTX 5090, с арифметикой против M3 Max.
- **5.19 МБ/с:** замер канала до узла в Болгарии и отказ предварительного расчёта от полностью локального плана.
- **Мак в расчёте экономики:** M5 Max 64 ГБ, он уже есть. Для M3 Max строк экономики в движке 22 нет. Выигрыш во времени у M3 Max взят из замеров.
- **Глубокий профиль Claude Code** в движке 22 не выгружает ни одного хода (занятость 0.00%), поэтому в этом тексте его пересечения не используются.
