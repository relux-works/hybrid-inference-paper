# Qwen3.8-27B long-context benchmark on a Mac

This kit repeats on another Mac the measurement made on a MacBook Pro M3 Max with 128 GB for the paper on hybrid
inference: prefill and decode of Qwen3.8-27B at context depths up to 249k tokens. The model, the llama.cpp commit,
the server settings and the benchmark script are the same, so the results compare directly. Any Apple Silicon Mac
with 48 GB of memory or more will do. A Russian version of this page is `README.ru.md`.

## Requirements
- An Apple Silicon Mac with 48 GB of memory or more.
- About 55 GB of free disk: the model takes 19 GB, the llama.cpp build about 1 GB, saved slots up to 28 GB. With less
  than 55 GB the script turns off the slot save/restore measurement, and 25 GB is enough.
  Imported GPU slots add about 45 GB for both 260k/1M imports and up to 36 GB for one restream copy:
  budget about 136 GB total with the 55 GB baseline (about 73 GB for 260k alone: 55 + 9 + 9 GB).
- Xcode Command Line Tools, cmake, git and python3 3.8 or newer. cmake installs with `brew install cmake`.
- Internet access to GitHub (llama.cpp sources) and Hugging Face (the model).
- AC power and 3–5 hours during which the machine does no other heavy work. Reading context up to 249k tokens takes
  the longest. The parallel-agents measurement at 64k and 128k can be skipped, which saves about an hour.

## How to run
Through an agent: open the kit folder in your agent (Claude Code, Codex or another) and ask it to do the task in
`AGENT_PROMPT.md`. The agent checks the machine, builds llama.cpp, downloads the model, runs the measurements, packs
the results and tells you briefly what came out.

By hand: `bash scripts/run-all.sh`.

## What to send
The archive `qwen27b-mac-bench-results-*.tar.gz` from the kit folder, to the person who asked you to run the kit. It
holds the measured numbers and the server logs, the llama.cpp and model versions, and the machine's chip, memory, GPU
core count and macOS version. Paths are replaced by placeholders before packing; the archive holds no computer name,
user name, serial number or files from the disk. The benchmark texts are generated by the script.

## How to stop
Ctrl-C. The scripts stop only their own llama-server, by its recorded PID. Everything the kit creates is inside its
folder, in `work/` and `results/`. To remove it all, delete the kit folder.

## Imported GPU slots (kit 1.4.0)

GPU step 60 writes **one-stream** slot files. Copy `parallel-depth-<depth>.bin` to
`work/slots-import/`, or set `SLOT_FROM` to their folder. Steps 56 and 57 compare/log
the import's SHA-256 and, for `-np > 1`, validate and restream a temporary copy into
`work/slots-restream/step-*/`. The server uses that copy's directory. A fallback to
fewer streams creates a new copy for the new count; a one-stream server reads the
import directly. Both SHA-256 values are in `results/kit.log`. Imports are never
changed; temporary copies are removed on success, failure and handled signals.

Allow additional free disk equal to the imported file plus `4 × (np − 1)` bytes
(and 1 MiB headroom). If the copy does not fit, the step logs a fallback to one
stream using the import directly. The copy uses bounded memory, including for the 36 GB 1M file.
The model, llama.cpp commit, KV types, flash attention and rope settings must match
on both machines. This conversion fixes stream layout only; CUDA/Metal numerical
agreement still requires its own measurement.

Step 00 understands both `lowpowermode` and macOS 26+ `powermode` (0 automatic,
1 low power, 2 high power). `system.json` records `low_power_mode` 1 when a known value
says low power and 0 when the known values say it is off, with `low_power_mode_status` "measured". When
neither key is present, or a value is one the kit does not know, it records `low_power_mode` null with
`low_power_mode_status` "unknown" and warns in `results/kit.log`; `low_power_mode_raw` keeps the pmset lines it read.

## Tools

| Tool | Command | Output |
|---|---|---|
| Kit steps (bash, Python 3, git, cmake, curl, shasum; caffeinate on macOS) | `bash scripts/run-all.sh` | Builds/models/slots in `work/`, logs and records in `results/` |
| Slot restreamer (Python 3 standard library) | `python3 scripts/kitlib.py restream-slot IN OUT --streams 8` | New OUT, both SHA-256 values on stdout; refuses existing OUT |
| Power parser | `pmset -g | python3 scripts/kitlib.py low-power-mode` | Integer 0/1; warnings on stderr |

Steps hash IN once per depth and pass `--input-sha256 <cached digest>` on fallback attempts; the helper hashes OUT once and reports both values as before. Standalone calls hash both files; disk exhaustion exits 3, other refused inputs exit 1.

The restreamer is pinned to c21284cd sequence magic/version 3 and the kit's hybrid
layout: one nonempty first attention stream, uniform K/V rows per section, 0/12-byte
cell extensions, known ggml cache types, V row or unquantized transposed layout,
one recurrent cell, F32 R/S rows on the remaining layers. PLE history, missing V
tensors, nonuniform dimensions, ambiguous layouts and other formats are refused.
The sequence file does not contain model dimensions or a recurrent-layer mask;
the matching-model requirement remains essential. All fields and the entire
recurrent section must parse, with no truncation or trailing bytes.
Attention positions must strictly increase and the recurrent position must match the last one; context-shifted slot files may be refused.
